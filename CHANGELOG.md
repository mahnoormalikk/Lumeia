## 2026-06-30 — Disable mobile font-boosting (root cause of the oversized scrolling-layers text)
On real phones (Safari + Chrome) the scrolling-layers body text rendered much larger than the headings, and the size changed when the address bar was hidden. That is mobile font-boosting (text auto-inflation), which the theme never disabled — there was no `text-size-adjust` anywhere in `theme.css`, the layout, or the assets. It inflated text-heavy paragraphs and blew up the layer heights on devices, while headless/desktop browsers (which don't boost) rendered them normally — which is why staging measurements looked fine but the owner's phone didn't. Added the standard normalize rule in `lumeia-custom.css`: `html { -webkit-text-size-adjust: 100%; text-size-adjust: 100%; }` so mobile renders text at its real CSS size (100% still allows pinch-zoom). Global, since boosting can hit any text-heavy mobile block. Verified the rule computes `100%` on `html` on staging and the scrolling-layers content stays 15px (no regression). NOTE: the boosting itself only reproduces on a real device, so the owner must confirm on his phone that the text is now normal size. This is the real cause behind the "scrolling-layers content too tall on mobile" work; the earlier image-shrinking treated the symptom. Theme Check clean. Merge with the Theme Editor CLOSED.

## 2026-06-28 — Arabic CSS cleaned up + selector finished (issue #53)
Two linked changes, verified on a staging preview in English AND Arabic, desktop AND mobile, before this PR (the new process — see PLAYBOOK).

**1. Replaced the brute-force global Arabic CSS.** A previous build (Ali, Urdu comments) forced Almarai on Arabic by slapping `!important` font-family and font-weight onto `*`, `span`, `button`, `[class*="heading"]`, `[class*="button"]`, plus a stray hardcoded `line-height: 85px`. It overrode the wrong variables (custom `--lumeia-font-*`, which the theme doesn't read) so it had to brute-force every element, and it broke any component whose class contained "heading"/"button".
